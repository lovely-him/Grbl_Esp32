## 2. 寄存器分析

### 关键寄存器说明

| 寄存器 | 值 | 含义 |
|--------|-----|------|
| **PC** | 0x400d6e5f | 程序计数器 → motors_direction() at Motors.cpp:492 |
| **PS** | 0x00060031 | 处理器状态寄存器 |
| **A0** | 0x80082138 | 返回地址 → stepper_pulse_func() |
| **A1** | 0x3ffbe780 | 栈指针（ISR 栈帧） |
| **A2** | 0x3ffbdb4c | 第一个参数（dir_mask） |
| **A3** | 0x3ffc14b8 | 第二个参数 |
| **A4-A6** | 0x00000000 | 全部为 0 |
| **SAR** | 0x00000000 | 移位量寄存器 |
| **EXCCAUSE** | 0x0000001c | 异常原因代码 = 28 (LoadProhibited) |
| **EXCVADDR** | 0x00000000 | **触发异常的内存地址** ← **空指针解引用** |

### 异常类型详解

**EXCCAUSE = 0x1c (28 = LoadProhibited)**
- 含义：读取无效内存地址
- 触发地址：EXCVADDR = 0x00000000（**空指针**）
- 崩溃原因：尝试通过空指针访问对象成员函数

### 寄存器分析结论

1. **EXCVADDR = 0x00000000**：典型的空指针解引用
2. **Core 1 was running in ISR context**：崩溃发生在中断服务程序中
3. **PC = 0x400d6e5f**：崩溃在 `myMotor[axis][0]->set_direction()` 调用
4. **A2 = 0x3ffbdb4c**：dir_mask 参数有效，但 myMotor 数组元素为 NULL

## 4. 根本原因

### 初始化顺序竞态条件

**Grbl.cpp:24-44 (grbl_init 函数，修改前)**：
```cpp
void grbl_init() {
    // ... 其他初始化 ...
    settings_init();  // 第 41 行：加载设置
    stepper_init();   // 第 42 行：配置步进器和定时器中断 ⚠️
    system_ini();     // 第 43 行：配置引脚
    init_motors();    // 第 44 行：初始化电机对象 ⚠️
    // ...
}
```

**问题本质**：
- `stepper_init()` 在 `init_motors()` **之前**被调用
- `stepper_init()` 注册了定时器中断，中断可能立即触发
- 中断处理函数访问 `myMotor` 数组，但此时数组还未初始化（全部为 NULL）

### 竞态条件流程图

```
时间轴 →
═══════════════════════════════════════════════════════════════════════════════

Main Thread (grbl_init)                    Timer ISR (onStepperDriverTimer)
─────────────────────────                  ─────────────────────────

stepper_init()
    ↓
Stepper_Timer_Init()
    ↓
timer_isr_register() ◄─────────────────────[定时器中断触发]
    ↓                                              ↓
[返回到 grbl_init]                         onStepperDriverTimer()
    ↓                                              ↓
system_ini()                               stepper_pulse_func()
    ↓                                              ↓
[准备调用 init_motors()]                   motors_direction()
    ↓                                              ↓
                                           myMotor[axis][0]->set_direction()
                                                   ↓
                                           💥 LoadProhibited (myMotor[axis][0] = NULL)

═══════════════════════════════════════════════════════════════════════════════
```

**关键时间窗口**：
```
T0: stepper_init() 调用 Stepper_Timer_Init()
T1: timer_isr_register() 注册中断处理函数
T2: 定时器中断触发（在 init_motors() 之前）
T3: motors_direction() 访问 myMotor[axis][0] → 崩溃 💥
```

**问题本质**：
- **TOCTOU (Time-of-Check-Time-of-Use) 竞态条件**
- 定时器中断在电机对象初始化完成之前就被触发

### 问题代码

**Motors.cpp:490-493 (崩溃点)**：
```cpp
for (int axis = X_AXIS; axis < n_axis; axis++) {
    bool thisDir = bitnum_istrue(dir_mask, axis);
    myMotor[axis][0]->set_direction(thisDir);  // ← 崩溃：myMotor[axis][0] = NULL
    myMotor[axis][1]->set_direction(thisDir);
}
```

**Grbl.cpp:42-44 (初始化顺序错误，修改前)**：
```cpp
stepper_init();   // ⚠️ 注册定时器中断
system_ini();
init_motors();    // ⚠️ 初始化 myMotor 数组（太晚了！）
```

## 5. 修复方案

### 代码修改

**Grbl.cpp:41-44 (修改后)**：
```cpp
settings_init();  // 加载 Grbl 设置
system_ini();     // 配置引脚
init_motors();    // ✅ 先初始化电机对象
stepper_init();   // ✅ 再配置步进器和定时器中断
```

### 修改说明

1. **调整初始化顺序**
   - 将 `init_motors()` 移到 `stepper_init()` **之前**
   - 确保 `myMotor` 数组在定时器中断注册之前完成初始化

2. **保持 system_ini() 在 init_motors() 之前**
   - `system_ini()` 配置 GPIO 引脚
   - `init_motors()` 需要使用这些引脚

3. **正确的初始化顺序**
   ```
   settings_init()  → 加载配置
   system_ini()     → 配置引脚
   init_motors()    → 初始化电机对象（包括 myMotor 数组）
   stepper_init()   → 注册定时器中断（此时 myMotor 已就绪）
   ```

### 解决的问题

1. **消除竞态条件** ✓
   - 定时器中断在 `myMotor` 数组初始化完成后才注册
   - 中断处理函数访问 `myMotor` 时保证非空

2. **防止空指针解引用** ✓
   - `motors_direction()` 访问 `myMotor[axis][0]` 时，对象已正确初始化
   - EXCVADDR = 0x00000000 错误不再发生

3. **确保初始化原子性** ✓
   - 电机对象初始化和定时器中断注册之间没有时间窗口
   - 避免 TOCTOU 竞态条件

4. **提高系统稳定性** ✓
   - 归零操作不再触发崩溃
   - 设备可以正常响应 `~` (CycleStart) 命令

## 总结

这是一个典型的**初始化顺序导致的竞态条件**问题：

1. **直接原因**：`myMotor[axis][0]` 为空指针，导致 LoadProhibited 异常
2. **根本原因**：`stepper_init()` 在 `init_motors()` 之前调用，定时器中断在电机对象初始化前触发
3. **触发场景**：用户发送 `~` 命令恢复运行，触发归零操作，在初始化过程中崩溃
4. **修复方法**：调整初始化顺序，将 `init_motors()` 移到 `stepper_init()` 之前

这个问题说明了在嵌入式系统中，**初始化顺序**和**中断安全**的重要性。定时器中断一旦注册，就可能随时触发，必须确保所有依赖的资源都已正确初始化。

### 关键教训

1. **中断注册时机**：在注册中断处理函数之前，必须确保所有被中断访问的资源已初始化
2. **初始化依赖关系**：明确各模块的初始化依赖关系，按正确顺序初始化
3. **防御性编程**：在中断处理函数中添加空指针检查（虽然不应该发生，但可以提供额外保护）
4. **测试覆盖**：初始化阶段的竞态条件很难通过常规测试发现，需要压力测试和边界测试
