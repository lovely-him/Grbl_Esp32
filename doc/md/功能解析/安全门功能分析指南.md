# Grbl_ESP32 安全门功能分析指南

## 概述

安全门(Safety Door)功能是Grbl_ESP32的重要安全特性之一，当安全门开关被触发时，系统会立即停止所有运动并切断主轴和冷却液输出，以确保操作人员的安全。本文档详细分析了安全门的工作机制及其状态管理逻辑。

## 安全门状态表示

### 状态显示格式
- **安全门闭合**（正常状态）：
  ```
  <Door:0|MPos:0.000,0.000,0.000|FS:0,0|WCO:0.000,0.000,0.000>
  <Door:0|MPos:0.000,0.000,0.000|FS:0,0|Ov:100,100,100>
  ```

- **安全门打开**（触发状态）：
  ```
  <Door:1|MPos:0.000,0.000,0.000|FS:0,0|Pn:D>
  <Door:1|MPos:0.000,0.000,0.000|FS:0,0|Pn:D>
  ```

### 各字段含义
- `Door:0` - 安全门关闭
- `Door:1` - 安全门打开
- `Pn:D` - 表示安全门(D)开关状态
- `FS:0,0` - 当前进给速度和主轴转速
- `Ov:100,100,100` - 进给、快速移动、主轴速度覆盖

## 安全门工作机制

### 1. 硬件配置
安全门通过以下宏定义在机器配置文件中启用：
```cpp
#define CONTROL_SAFETY_DOOR_PIN GPIO_NUM_X
```

### 2. 状态检测
安全门状态检测函数位于[System.cpp](file:///e:/JianHao/ESP_IDF/202601140_cnc/Grbl_Esp32/Grbl_Esp32/src/System.cpp)：
```cpp
uint8_t system_check_safety_door_ajar() {
#ifdef ENABLE_SAFETY_DOOR_INPUT_PIN
    return system_control_get_state().bit.safetyDoor;
#else
    return false;  // 输入引脚未启用，返回关闭状态
#endif
}
```

### 3. 状态转换
当安全门打开时，系统执行以下操作：

1. **立即停止所有运动**
2. **切断主轴和冷却液**
3. **进入SafetyDoor状态**
4. **显示"[MSG:Check door]"消息**

### 4. 状态管理
安全门相关的状态管理在[Protocol.cpp](file:///e:/JianHao/ESP_IDF/202601140_cnc/Grbl_Esp32/Grbl_Esp32/src/Protocol.cpp)中实现：

```cpp
// 执行安全门停止，包括进给保持并禁用主轴/冷却液
if (rt_exec_state.bit.safetyDoor) {
    report_feedback_message(Message::SafetyDoorAjar);
    // ... 状态管理逻辑 ...
    if (sys.state != State::Sleep) {
        sys.state = State::SafetyDoor;
    }
    rt_exec_state.bit.safetyDoor = false;
    // 标志不会随门关闭而改变，确保停车运动执行
    sys.suspend.bit.safetyDoorAjar = true;
}
```

## 为何安全门关闭后不能使用$H或$X

### 1. 状态恢复机制
当安全门关闭后，系统并不会自动回到Idle状态，而是保持在Hold状态，直到执行恢复操作。这是因为安全门机制设计为：

- **安全第一**：强制用户确认环境安全后手动恢复
- **状态一致性**：确保在安全门打开期间的所有操作都被妥善处理

### 2. 恢复过程
安全门关闭后的恢复过程如下：

```cpp
// 在protocol_exec_rt_suspend()中
if (sys.state == State::SafetyDoor) {
    if (!sys.suspend.bit.safetyDoorAjar) {  // 门已关闭
        if (sys.suspend.bit.restoreComplete) {
            sys.state = State::Idle;  // 回到空闲状态
        } else if (sys.suspend.bit.retractComplete) {
            sys.suspend.bit.initiateRestore = true;  // 标志恢复开始
        }
    }
}
```

### 3. 恢复命令
安全门关闭后，正确的恢复流程是：

1. **使用`~`(循环启动)命令**，而不是$H或$X
2. 系统会自动执行恢复动作：
   - 重新定位到原来的位置
   - 恢复主轴和冷却液状态
   - 返回到Idle状态

### 4. $H和$X命令限制
- **$X**(解锁报警)：仅用于解除Alarm状态，安全门状态不是报警状态
- **$H**(归零)：仅在Idle或Alarm状态下可用，不能在SafetyDoor/Hold状态下执行

## 系统状态转换

### 状态转换流程
```
Idle ←→ Cycle ↔ Hold ↔ SafetyDoor
  ↑      ↓      ↓       ↓
Alarm ←--+------+-------+
```

### 关键状态说明
- **Idle**：系统空闲，可接受$H、$X等命令
- **Cycle**：系统运行中
- **Hold**：系统暂停（进给保持）
- **SafetyDoor**：安全门打开，系统处于特殊的保持状态

## 调试和故障排查

### 1. 检查安全门配置
确保在机器配置文件中正确定义了安全门引脚：
```cpp
#define CONTROL_SAFETY_DOOR_PIN GPIO_NUM_X
```

### 2. 检查引脚状态
通过状态报告中的`Pn:D`标志确认安全门引脚的实际状态。

### 3. 恢复操作
当安全门关闭后，使用`~`(循环启动)命令恢复系统运行，而不是$H或$X。

## 总结

安全门功能是Grbl_ESP32中重要的安全机制，其设计目的是确保操作人员的安全。当安全门被触发时，系统会立即停止所有运动并切断动力输出。安全门关闭后，必须使用`~`(循环启动)命令进行恢复，而不是$H或$X，因为安全门状态不同于报警状态，需要专门的恢复流程来确保安全。
