## 1. 概述

Grbl_Esp32 实现了一套完整的网络服务体系，支持多种通信协议和设备发现机制。这些服务可以分为以下几类：

### 1.1 服务分类

#### 应用层服务 (TCP)
- **HTTP Web Server** - 提供 Web 界面和 REST API
- **WebSocket Server** - 实时双向通信
- **Telnet Server** - 命令行远程控制
- **File Transfer Server** - 高效的二进制文件传输

#### 设备发现服务 (UDP)
- **DNS Server** - Captive Portal 支持 (AP 模式)
- **SSDP/UPnP** - Windows 网络邻居发现 (STA 模式)
- **mDNS** - 本地域名解析 (STA 模式)

#### 外部通知服务
- **Notification Service** - Pushover、LINE、Email 推送

### 1.2 设计特点

1. **模块化设计**: 每个服务可独立启用/禁用
2. **WiFi 模式感知**: 根据 STA/AP 模式自动调整服务
3. **资源优化**: 使用流式处理减少内存占用
4. **可配置性**: 端口号和参数可运行时配置

### 1.3 文件位置

所有网络服务实现位于 `Grbl_Esp32/src/WebUI/` 目录：

```
WebUI/
├── WebServer.cpp/h          # HTTP 和 WebSocket
├── TelnetServer.cpp/h       # Telnet
├── FileTransferServer.cpp/h # 文件传输
├── WifiServices.cpp/h       # 服务管理器
├── WifiConfig.h             # 配置定义
├── WebSettings.cpp          # 设置初始化
└── NotificationsService.cpp/h # 通知服务
```

## 3. HTTP Web Server (端口 80)

### 3.1 功能概述

HTTP Web Server 是 Grbl_Esp32 的核心网络服务，提供：
- 完整的 Web 控制界面
- REST API 接口
- 文件管理 (SPIFFS 和 SD 卡)
- 固件 OTA 更新
- 实时状态监控

### 3.2 实现细节

**文件位置**: `Grbl_Esp32/src/WebUI/WebServer.cpp/h`

**初始化代码** (`WebServer.cpp:104-210`):

```cpp
bool Web_Server::begin() {
    // 1. 检查是否启用
    if (http_enable->get() == 0) {
        return false;
    }

    // 2. 读取配置端口
    _port = http_port->get();  // 默认 80

    // 3. 创建 Web 服务器实例
    _webserver = new WebServer(_port);

    // 4. 创建 WebSocket 服务器 (端口 = HTTP + 1)
    _socket_server = new WebSocketsServer(_port + 1);
    _socket_server->begin();
    _socket_server->onEvent(handle_Websocket_Event);
    Serial2Socket.attachWS(_socket_server);

    // 5. 注册路由
    _webserver->on("/", HTTP_GET, handle_root);
    _webserver->on("/command", HTTP_ANY, handle_web_command);
    _webserver->on("/files", HTTP_ANY, handleFileList);
    _webserver->on("/updatefw", HTTP_POST, handleUpdate);
    // ... 更多路由

    // 6. 启动服务器
    _webserver->begin();

    return true;
}
```

### 3.3 主要路由

| 路径 | 方法 | 功能 | 处理函数 |
|------|------|------|---------|
| `/` | GET | 主页 | `handle_root()` |
| `/command` | ANY | 执行 G-code/命令 | `handle_web_command()` |
| `/files` | ANY | 文件列表 | `handleFileList()` |
| `/upload` | POST | 上传文件到 SPIFFS | `handleFileUpload()` |
| `/updatefw` | POST | 固件更新 | `handleUpdate()` |
| `/description.xml` | GET | SSDP 设备描述 | `handle_SSDP()` |
| `/generate_204` | GET | Android Captive Portal | 重定向到 `/` |
| `/fwlink` | GET | Windows Captive Portal | 重定向到 `/` |

### 3.10 常见问题

- 检查 `ENABLE_HTTP` 是否定义

- 检查防火墙设置
- 验证 IP 地址是否正确

**问题 2: Captive Portal 不弹出**
- 确认 WiFi 模式为 AP
- 确认 `ENABLE_CAPTIVE_PORTAL` 已定义
- 尝试手动访问 `http://192.168.0.1`

**问题 3: 文件上传失败**
- 检查 SPIFFS 是否已格式化
- 检查可用空间 (SPIFFS 通常 1-2MB)
- 检查文件名是否合法 (避免特殊字符)

## 5. Telnet Server (端口 8080)

### 5.1 功能概述

Telnet Server 提供命令行远程控制，用于：
- 远程执行 G-code 命令
- 实时查看系统状态
- 调试和诊断
- 脚本自动化控制

### 5.2 实现细节

**文件位置**: `Grbl_Esp32/src/WebUI/TelnetServer.cpp/h`

**初始化代码** (`TelnetServer.cpp:47-67`):

```cpp
bool Telnet_Server::begin() {
    // 1. 检查是否启用
    if (telnet_enable->get() == 0) {
        return false;
    }

    // 2. 读取配置端口
    _port = telnet_port->get();  // 默认 8080

    // 3. 创建 Telnet 服务器
    _telnetserver = new WiFiServer(_port, MAX_TLNT_CLIENTS);
    _telnetserver->setNoDelay(true);  // 禁用 Nagle 算法
    _telnetserver->begin();

    // 4. 打印启动消息
    grbl_sendf(CLIENT_ALL, "[MSG:TELNET Started %d]\r\n", _port);

    _setupdone = true;
    return true;
}
```

### 5.3 关键参数

**配置** (`TelnetServer.h:31-34`):
```cpp
static const int MAX_TLNT_CLIENTS = 1;        // 最多 1 个客户端
static const int TELNETRXBUFFERSIZE = 1200;   // 接收缓冲区
static const int FLUSHTIMEOUT = 500;          // 刷新超时 (ms)
```

**特性**:
- 仅支持 1 个并发连接
- 新连接会自动断开旧连接
- 禁用 Nagle 算法以减少延迟

### 5.4 客户端管理

**连接处理** (`TelnetServer.cpp:79-101`):

```cpp
void Telnet_Server::clearClients() {
    // 检查新客户端
    if (_telnetserver->hasClient()) {
        WiFiClient newClient = _telnetserver->available();

        // 如果已有客户端，断开旧连接
        if (_telnetClients[0] && _telnetClients[0].connected()) {
            _telnetClients[0].stop();
        }

        // 接受新客户端
        _telnetClients[0] = newClient;

        #ifdef ENABLE_TELNET_WELCOME_MSG
            // 发送欢迎消息
            _telnetClients[0].println("Connected to Grbl_ESP32");
        #endif
    }
}
```

### 6.3 协议设计

#### 6.3.1 包格式

**请求包结构**:
```
[0xAB][CMD][LEN_H][LEN_L][IDX_H][IDX_L][DATA...][CHK_H][CHK_L]

字段说明:
- 0xAB: 帧头 (固定)
- CMD: 命令类型 (1 字节)
  - 0x01: Header (文件名包)
  - 0x02: Data (数据包)
  - 0x03: Cancel (取消包)
- LEN_H/LEN_L: 数据长度 (大端序, 2 字节)
- IDX_H/IDX_L: 包序号 (大端序, 2 字节)
- DATA: 数据内容 (0-32760 字节)
- CHK_H/CHK_L: 校验和 (大端序, 2 字节)
```

**响应包结构** (固定 8 字节):
```
[0xAB][STATUS][LEN_H][LEN_L][IDX_H][IDX_L][CHK_H][CHK_L]

字段说明:
- 0xAB: 帧头 (固定)
- STATUS: 响应状态 (1 字节)
  - 0x01: Success (成功, 请求下一个包)
  - 0x02: ProtocolError (协议错误)
  - 0x03: ServerError (服务器错误)
- LEN_H/LEN_L: 回显数据长度
- IDX_H/IDX_L: 回显包序号
- CHK_H/CHK_L: 校验和
```

#### 6.3.2 传输流程

```
客户端                           服务器
  |                                |
  |--- Header包 (文件名) -------->|
  |                                | 创建文件
  |<------ Success响应 -----------|
  |                                |
  |--- Data包 #0 --------------->|
  |                                | 写入数据
  |<------ Success响应 -----------|
  |                                |
  |--- Data包 #1 --------------->|
  |                                | 写入数据
  |<------ Success响应 -----------|
  |                                |
  |--- Data包 #2 (校验失败) ---->|
  |                                | 回滚文件位置
  |<------ ProtocolError ---------|
  |                                |
  |--- Data包 #2 (重传) -------->|
  |                                | 写入数据
  |<------ Success响应 -----------|
  |                                |
  ... (继续传输) ...
  |                                |
  |--- 断开连接 ----------------->|
  |                                | 关闭文件
```

**算法** (`FileTransferServer.cpp:437-484`):
```cpp
uint16_t FileTransferServer::calculateChecksum(
    const uint8_t* data, size_t length, PacketType type) {

    uint16_t checksum = 0;

    // 累加包头 (6 字节)
    checksum += 0xAB;  // 帧头
    checksum += static_cast<uint8_t>(type);
    checksum += (length >> 8) & 0xFF;  // LEN_H
    checksum += length & 0xFF;         // LEN_L
    checksum += (_expectedPacketIndex >> 8) & 0xFF;  // IDX_H
    checksum += _expectedPacketIndex & 0xFF;         // IDX_L

    // 累加数据部分
    for (size_t i = 0; i < length; i++) {
        checksum += data[i];
    }

    return checksum;
}
```

**特点**:
- 16 位累加校验和
- 包含包头和数据
- 碰撞概率: 1/65536

### 6.5 使用方法

#### 方法 1: Python 客户端示例

```python
import socket
import struct

def send_file(ip, port, filename, data):
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.connect((ip, port))

    try:
        # 1. 发送文件名包
        header_data = filename.encode('utf-8')
        send_packet(sock, 0x01, 0, header_data)
        response = receive_response(sock)

        if response['status'] != 0x01:
            raise Exception("Header packet failed")

        # 2. 分块发送数据
        chunk_size = 1024
        packet_index = 0

        for i in range(0, len(data), chunk_size):
            chunk = data[i:i+chunk_size]
            send_packet(sock, 0x02, packet_index, chunk)
            response = receive_response(sock)

            if response['status'] != 0x01:
                # 重传
                send_packet(sock, 0x02, packet_index, chunk)
                response = receive_response(sock)

            packet_index += 1

        print(f"文件传输完成: {filename}")

    finally:
        sock.close()

def send_packet(sock, cmd, index, data):
    # 构造包
    length = len(data)
    packet = bytearray()
    packet.append(0xAB)  # 帧头
    packet.append(cmd)   # 命令
    packet.extend(struct.pack('>H', length))  # 长度 (大端序)
    packet.extend(struct.pack('>H', index))   # 序号 (大端序)
    packet.extend(data)  # 数据

    # 计算校验和
    checksum = sum(packet) & 0xFFFF
    packet.extend(struct.pack('>H', checksum))

    # 发送
    sock.sendall(packet)

def receive_response(sock):
    # 接收 8 字节响应
    response = sock.recv(8)

    if len(response) != 8 or response[0] != 0xAB:
        raise Exception("Invalid response")

    return {
        'status': response[1],
        'length': struct.unpack('>H', response[2:4])[0],
        'index': struct.unpack('>H', response[4:6])[0],
        'checksum': struct.unpack('>H', response[6:8])[0]
    }

# 使用示例
with open('test.gcode', 'rb') as f:
    data = f.read()
    send_file('192.168.1.100', 8081, '/test.gcode', data)
```

### 12.4 File Transfer 完整测试

**Python 测试脚本**:

```python
#!/usr/bin/env python3
# file_transfer_test.py

import socket
import struct
import sys

def send_file(ip, port, filename, data):
    """发送文件到 File Transfer Server"""
    print(f"连接到 {ip}:{port}...")
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(10)

    try:
        sock.connect((ip, port))
        print("连接成功")

        # 1. 发送文件名包
        print(f"发送文件名: {filename}")
        header_data = filename.encode('utf-8')
        send_packet(sock, 0x01, 0, header_data)
        response = receive_response(sock)

        if response['status'] != 0x01:
            raise Exception(f"Header packet failed: status={response['status']}")

        print("文件创建成功")

        # 2. 分块发送数据
        chunk_size = 1024
        packet_index = 0
        total_chunks = (len(data) + chunk_size - 1) // chunk_size

        for i in range(0, len(data), chunk_size):
            chunk = data[i:i+chunk_size]
            print(f"发送数据包 {packet_index + 1}/{total_chunks} ({len(chunk)} 字节)...")

            retry_count = 0
            while retry_count < 3:
                send_packet(sock, 0x02, packet_index, chunk)
                response = receive_response(sock)

                if response['status'] == 0x01:
                    break  # 成功
                elif response['status'] == 0x02:
                    print(f"  协议错误, 重试 {retry_count + 1}/3...")
                    retry_count += 1
                else:
                    raise Exception(f"Server error: status={response['status']}")

            if retry_count >= 3:
                raise Exception("重试次数超限")

            packet_index += 1

        print(f"文件传输完成: {filename} ({len(data)} 字节)")

    except socket.timeout:
        print("错误: 连接超时")
        sys.exit(1)
    except Exception as e:
        print(f"错误: {e}")
        sys.exit(1)
    finally:
        sock.close()

def send_packet(sock, cmd, index, data):
    """发送数据包"""
    length = len(data)
    packet = bytearray()
    packet.append(0xAB)  # 帧头
    packet.append(cmd)   # 命令
    packet.extend(struct.pack('>H', length))  # 长度 (大端序)
    packet.extend(struct.pack('>H', index))   # 序号 (大端序)
    packet.extend(data)  # 数据

    # 计算校验和
    checksum = sum(packet) & 0xFFFF
    packet.extend(struct.pack('>H', checksum))

    # 发送
    sock.sendall(packet)

def receive_response(sock):
    """接收响应包"""
    response = sock.recv(8)

    if len(response) != 8:
        raise Exception(f"Invalid response length: {len(response)}")

    if response[0] != 0xAB:
        raise Exception(f"Invalid response header: 0x{response[0]:02X}")

    return {
        'status': response[1],
        'length': struct.unpack('>H', response[2:4])[0],
        'index': struct.unpack('>H', response[4:6])[0],
        'checksum': struct.unpack('>H', response[6:8])[0]
    }

if __name__ == '__main__':
    if len(sys.argv) < 4:
        print(f"用法: {sys.argv[0]} <IP> <端口> <本地文件>")
        sys.exit(1)

    ip = sys.argv[1]
    port = int(sys.argv[2])
    local_file = sys.argv[3]

    # 读取文件
    with open(local_file, 'rb') as f:
        data = f.read()

    # 发送文件
    remote_file = '/' + local_file.split('/')[-1]
    send_file(ip, port, remote_file, data)
```

## 13. 安全性分析

### 13.1 安全风险评估

| 风险类别 | 严重程度 | 影响 | 缓解措施 |
|---------|---------|------|---------|
| 密码明文传输 | 高 | 凭证泄露 | 使用 WPA2, 避免公共网络 |
| 默认凭证 | 中 | 未授权访问 | 修改默认密码 |
| 无 HTTPS/TLS | 高 | 数据窃取 | 限制在可信网络使用 |
| DNS 欺骗 | 中 | 重定向攻击 | 仅在 AP 模式启用 Captive Portal |
| 缓冲区溢出 | 低 | 服务崩溃 | 代码已有长度检查 |
| DoS 攻击 | 中 | 服务不可用 | 限制连接数, 设置超时 |

### 13.2 身份验证实现分析

**当前实现** (`Config.h:127-131`):
```
Warning! The current authentication implementation is too weak to provide
security against an attacker, since passwords are stored and transmitted
"in the clear" over unsecured channels.
```

**问题**:
1. 密码以明文存储在 SPIFFS
2. 密码通过 HTTP 明文传输
3. 无 HTTPS/TLS 支持
4. Session ID 可能被劫持

**建议**:

    └─ 检查防火墙/网络

### 15.2 服务特定问题

#### HTTP/WebSocket 问题

**问题**: 无法访问 Web 界面

**排查步骤**:
```bash
# 1. 检查端口是否开放
telnet 192.168.1.100 80

# 2. 检查 HTTP 响应
curl -v http://192.168.1.100

# 3. 检查日志
# 串口输出中查找:
# [MSG:HTTP Started on port 80]
```

**可能原因**:
- `ENABLE_HTTP` 未定义
- HTTP 服务被运行时禁用 (`$ESP120=0`)
- 端口被占用
- 内存不足 (OOM)

#### Telnet 问题

**问题**: Telnet 连接被拒绝

**排查步骤**:
```bash
# 1. 检查端口
nc -zv 192.168.1.100 8080

# 2. 尝试连接
telnet 192.168.1.100 8080

# 3. 检查是否有其他客户端占用
# (Telnet 仅支持 1 个客户端)
```

**可能原因**:
- `ENABLE_TELNET` 未定义
- Telnet 被运行时禁用 (`$ESP130=0`)
- 已有客户端连接 (最多 1 个)

#### File Transfer 问题

**问题**: 文件传输失败

**排查步骤**:
```bash
# 1. 检查端口
nc -zv 192.168.1.100 8081

# 2. 检查 SD 卡状态
# 串口命令: $SD/Status

# 3. 启用详细日志
# FileTransferServer.cpp: #define FTS_LOG_LEVEL 4
```

**可能原因**:
- SD 卡未插入或未初始化
- SD 卡空间不足
- 文件名包含非法字符
- 校验和错误 (网络丢包)
- 超时 (网络延迟过高)

#### mDNS 问题

**问题**: 无法解析 .local 域名

**排查步骤**:
```bash
# 1. Ping 测试
ping grblesp.local

# 2. nslookup 测试
nslookup grblesp.local

# 3. mDNS 监听
sudo tcpdump -i wlan0 'udp port 5353'
```

**可能原因**:
- WiFi 模式为 AP (mDNS 仅在 STA 模式启用)
- 客户端不支持 mDNS:
  - Windows: 需安装 Bonjour
  - Linux: 需安装 avahi-daemon
- 防火墙阻止 UDP 5353
- 主机名冲突 (网络中有重名设备)

## 16. 总结和建议

### 16.1 网络服务架构评估

#### 优点

**1. 模块化设计**
- 每个服务独立实现
- 可单独启用/禁用
- 便于维护和扩展

**2. 资源优化**
- 流式处理减少内存占用
- NoDelay 减少延迟
- 合理的缓冲区大小

**3. 多协议支持**
- HTTP/WebSocket: Web 界面
- Telnet: 命令行控制
- File Transfer: 高效文件传输
- mDNS/SSDP: 自动发现

**4. WiFi 模式感知**
- STA: 适合集成到现有网络
- AP: 适合首次配置和独立使用
- 自动适配服务 (mDNS/SSDP/DNS)

#### 不足

**1. 安全性**
- ❌ 无 HTTPS/TLS 支持
- ❌ 密码明文传输和存储
- ❌ 无证书验证
- ⚠️ 仅适合可信私有网络

**2. 并发限制**
- Telnet: 仅 1 个客户端
- File Transfer: 仅 1 个客户端
- HTTP: 受内存限制 (通常 4-8 个)

**3. 错误处理**
- 部分服务缺少详细的错误信息
- 超时机制不够完善
- 日志级别不统一

### 16.2 使用场景建议

#### 场景 1: 首次配置

**推荐配置**:
- WiFi 模式: AP
- 启用服务: HTTP, DNS (Captive Portal)
- 禁用服务: Telnet, File Transfer, mDNS, SSDP

**理由**:
- Captive Portal 简化配置流程
- 减少内存占用
- 提高稳定性

#### 场景 2: 局域网使用

**推荐配置**:
- WiFi 模式: STA
- 启用服务: HTTP, WebSocket, Telnet, File Transfer, mDNS
- 可选服务: SSDP (Windows 环境)

**理由**:
- 完整功能
- mDNS 简化访问
- File Transfer 高效传输 G-code

#### 场景 3: 生产环境

**推荐配置**:
- WiFi 模式: STA
- 启用服务: HTTP, WebSocket, File Transfer
- 禁用服务: Telnet, mDNS, SSDP, Captive Portal
- 网络隔离: 内部 VLAN

**理由**:
- 减少攻击面
- 限制设备发现
- 提高安全性

#### 场景 4: 离线使用

**推荐配置**:
- WiFi 模式: AP
- 启用服务: HTTP, File Transfer
- 禁用服务: mDNS, SSDP, Notifications

**理由**:
- 无需外部网络
- 减少资源占用
- 简化部署
